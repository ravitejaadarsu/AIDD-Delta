# Phase: QA

Purpose: post-implementation review with adversarial verification, an exhaustive
test-engineering pass, clean-state E2E + mutation, post evidence, the AC matrix, work-item
tally, the Layer-2 final audit, and a single consolidated critic verdict. Only CONFIRMED
findings, executed test FAILs, a REJECT verdict, and an AC that exits the interrogation →
negotiation → adjudication ladder as DISPUTED or ruled DEFECT block.

## Steps

Phase boundary: rebuild the snapshot pack
(`bash .aidd/framework/scripts/build-snapshot.sh pre-qa` per
`../protocol/context-snapshots.md`) before Step 1.

1. **Post-implementation review** — fan out Reviewer (`../roles/reviewer.md`) `mode: post`
   over the full Construction diff, dimensions: correctness, security, performance,
   test-coverage, spec-compliance (delta dimension added by the delta-review protocol — see
   reviewer.md mode list) → `qa/findings-<dimension>.md`. In parallel: Security
   Auditor (`../roles/security-auditor.md`) → `qa/security-report.md` (incl. the CWE/CVSS
   threat matrix).
2. **Collate & dedupe** (orchestrator): same file+line+claim merges keeping highest
   severity → numbered master list `qa/findings.md`.
3. **Adversarial verification** — fan out Adversarial Verifier
   (`../roles/adversarial-verifier.md`), one per CRITICAL/HIGH finding (file-grouped if
   >12; cap 6) → `qa/verdicts.md`. CONFIRMED = blocking; PLAUSIBLE + MEDIUM/LOW =
   advisory; REFUTED = dropped with evidence.
4. **Test-design debate** — Master Agent + Auditor challenge the published TC matrices
   before execution (test-debate.md); budget per the debate protocol.
5. **Exhaustive testing** — fan out Test Engineer (`../roles/test-engineer.md`), one per
   test category (functional-happy-path, negative-error-handling, boundary-edge,
   impossible-abuse, api-contract, state-concurrency-idempotency, regression-compat,
   performance-smoke; cap 6). Each designs AND executes an exhaustive case matrix →
   `qa/tests/<category>.md`; orchestrator consolidates → `qa/test-report.md`. Every
   executed FAIL becomes a fix-loop defect. Sets `exhaustive_tests_passed`.
   **Execution debate**: as each category's results land the Auditor may contest specific
   TCs and the tester re-executes only those (test-debate.md); budget per the debate
   protocol.
6. **Fix loop** (max 3 iterations, shared budget) — consumes BOTH CONFIRMED findings and
   test-report FAILs:
   - Group defects by ownership; re-dispatch the owning Builder with them appended to its
     story file. Fixes are TDD (reproducing test first).
   - `scope=ARCHITECTURE` findings skip the loop → backflow (below).
   - Re-run integration; re-run ONLY affected reviewer dimensions and test categories.
7. **E2E verification** — E2E Verifier (`../roles/e2e-verifier.md`): clean-state run of ALL
   canonical commands + mutation testing → `qa/verification-report.md`. Red re-enters the
   fix loop. Sets tests_green / e2e_verified / mutation_floor_met.
8. **Post evidence** — Evidence Capturer `stage: post` → `evidence/post/` + manifest +
   perf-budget check → evidence_captured / perf_within_budget. (Optionally re-dispatch the
   Impact Analyst in QA mode to confirm actual reach matched `impact-report.md`.)
9. **AC matrix** — AC Assessor (`../roles/ac-assessor.md`) → `ac-matrix.md`; FAILs feed the
   fix loop → acs_verified.
10. **Results debate** — disputed PASSes in the consolidated `qa/test-report.md` are
    re-proven live (test-debate.md); budget per the debate protocol.
11. **Tally reconciliation** — dispatch Tally (`../roles/tally.md`) → `qa/tally.md`: every
    tracked work item (Jira tickets, PRD ACs, stories) joined to the stories that claimed
    it, the diff files that realized it, the tests that prove it, and its pre/post evidence
    rows; verdict per row `RECONCILED | GAP`, plus an `## Orphans` section for diff files no
    story owns. Tally routes and never blocks: AC-proof notes go to the AC-matrix fix loop,
    orphaned-diff findings go to adversarial verification. Orchestrator folds the result
    into `tally_reconciled` (passed only with every row RECONCILED and no unrouted orphan).
12. **Auditor final audit** — dispatch Auditor (`../roles/auditor.md`) over `qa/tests/*`,
    `qa/findings*`, and `ac-matrix.md` row by row; interrogation max **2** rounds per
    subject (`../protocol/interrogation.md`) → `audit/interrogation/<subject-id>-verdict.md`,
    every claimed AC exactly `PROVEN` or `DISPUTED`; a `## Auditor Report` section is
    appended to each covered story file. Sets `auditor_approved` — passed only when every AC
    is PROVEN or carries a terminal ruling from step 13.
13. **Negotiation** (only when step 12 left a DISPUTED AC) — per
    `../protocol/negotiation.md`: Auditor position ↔ Master Agent response, **accept** →
    ruling `DEFECT` straight into the fix loop, **contest** → next exchange, max **2**
    exchanges per AC; the short-circuit rule skips negotiation entirely where the monitoring
    note already concurs the work is deficient. Budget spent with the Master Agent still
    contesting escalates to Supervisor adjudication at step 17, ruling
    `PROVEN | DEFECT | UNRESOLVABLE`: `DEFECT` re-enters the fix loop, `UNRESOLVABLE` makes
    G3 forced-human in both autonomy modes. Every outcome is exactly one line in
    `audit/negotiation-log.md`, mirrored into change-state `audit`.
14. **Test report approval & story annotation** — present `qa/test-report.md`. On approval
    (`take-care`: auto unless a FAIL remains) record `g_test_report` and write a
    `## Test Report` section into each affected story (`../protocol/gates.md`).
15. Orchestrator computes the QA verdict + score (see `50-delivery.md`), sets
    qa_findings_resolved / security_clean.
16. **Critic verdict** — dispatch Critic (`../roles/critic.md`) → `qa/critic-verdict.md`:
    one consolidated verdict (APPROVE / APPROVE WITH CONDITIONS / REJECT) synthesizing the
    verification report, adversarial verdicts, test report, AC matrix, impact report,
    security report, and supervision. Sets `critic_approved` (APPROVE→passed,
    CONDITIONS→passed with the conditions recorded, REJECT→failed → re-enter fix loop or
    escalate). Conditions/blockers go verbatim into the PR body.
17. **Supervisor audit over the super-context** (`../roles/supervisor.md`) — process
    compliance across every worker artifact plus `audit/monitoring/*`,
    `audit/interrogation/*`, `audit/negotiation-log.md`, `audit/debate/*`, `qa/tally.md`,
    the Critic verdict, `supervision/audit.log`, and change state; it also adjudicates any
    negotiation that exhausted its budget at step 13 → **GATE G3** (`g3_premerge`).

## Backflow (once per run)

Architect ADR amendment → Epic Scoper delta stories (disjointness re-checked) → G2
re-gates (`G2.n`) → delta Construction → QA over the delta diff + final full E2E.
A second architecture-scope confirmation = run FAIL + escalation.

## Fix-loop exhaustion

Verdict FAIL; G3 forced-human even in take-care. Options: accept-with-waiver, redirect
(notes → one bonus iteration), abort.

## Exit checklist

- [ ] zero open CONFIRMED findings; advisory itemized
- [ ] exhaustive test report PASS (`exhaustive_tests_passed`); no open executed FAIL
- [ ] critic verdict APPROVE or APPROVE WITH CONDITIONS (`critic_approved`); no REJECT
- [ ] every affected story annotated with its Test Report link (g_test_report recorded)
- [ ] verification report green, clean-state, with evidence
- [ ] mutation ≥ floor; coverage ≥ target (or CONCERNS)
- [ ] evidence/post + manifest complete; perf within budget
- [ ] AC matrix: every AC PASS
- [ ] Auditor final audit clean (`auditor_approved` passed): every AC PROVEN or terminally
      ruled
- [ ] `tally_reconciled` passed: every row RECONCILED, no unrouted orphan (or the gaps
      explicitly waived at G3)
- [ ] negotiation log terminal: every disputed AC closed by short-circuit, accept, or
      Supervisor ruling — no dangling DISPUTED
- [ ] G3 approved
